# Розгортання на сервері КНУ

Сайт — лише статичні файли, тож серверу потрібен будь-який веб-сервер (Apache чи nginx), без PHP, баз даних і Node.
Доступу команди до сервера немає, тому розгортання побудоване так, щоб він і не знадобився.

## Як це влаштовано

```
запит на злиття ──► CI: збирання, повнота вмісту, тести, Lighthouse ──► перегляд pr-preview/pr-N на GitHub Pages
злиття в main  ──► Release: dist → ce-knu-site.tar.gz + .zip + .sha256 у GitHub Releases (latest)
сервер КНУ     ──► раз на 15 хв забирає latest, звіряє SHA-256, атомарно перемикає версію
```

Збірка для сервера має адресу `https://ce.knu.ua` і корінь `/`. Інша адреса чи підкаталог — змінні репозиторію
`SITE_URL` і `BASE_PATH` (Settings → Variables) або ручний запуск Release з параметрами.

## Варіант А (рекомендовано): сервер сам забирає збірку

Адміністратор робить один раз, від імені власника каталогу сайту:

```sh
curl -fsSL https://raw.githubusercontent.com/<власник>/<репозиторій>/main/deploy/update-site.sh -o /usr/local/bin/ce-site-update
chmod 755 /usr/local/bin/ce-site-update
REPO=<власник>/<репозиторій> ROOT=/var/www/ce.knu.ua ce-site-update     # перше встановлення
crontab -e   # */15 * * * * REPO=<власник>/<репозиторій> ROOT=/var/www/ce.knu.ua /usr/local/bin/ce-site-update >> /var/log/ce-site.log 2>&1
```

- DocumentRoot → `/var/www/ce.knu.ua/current` (символьне посилання на поточну версію; 5 попередніх лишаються для відкату).
- Відкат: `REPO=… ROOT=… ce-site-update rollback` — попередня версія закріплюється; автооновлення повертає `ce-site-update unpin`.
- Якщо DocumentRoot змінити не можна (спільний хостинг): `MODE=rsync DOCROOT=/шлях/до/public_html`.
- Потрібні лише `curl`, `tar`, `sha256sum` (і `rsync` для MODE=rsync). Сервер не приймає вхідних з'єднань і не зберігає жодних ключів:
  репозиторій публічний, архів перевіряється за SHA-256.

## Варіант Б: CI копіює збірку на сервер

Якщо адміністратор дасть SSH/SFTP-обліковий запис лише з правом запису в каталог сайту, додайте секрети репозиторію
`DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH`, `DEPLOY_KEY` — і Release після кожного злиття виконає `rsync --delete`.
Ключ створює адміністратор; у чат, у репозиторій і агентам його не передають.

## Варіант В: вручну

GitHub → Releases → Latest → `ce-knu-site.zip` → розпакувати в каталог сайту (через панель хостингу чи FTP), замінивши старі файли.

## Налаштування веб-сервера

- Apache: `public/.htaccess` і `public/en/.htaccess` уже в збірці — сторінки 404 обома мовами, кешування `/_astro/`, стиснення.
- nginx: приклад — `deploy/nginx.conf`.
- Адреси закінчуються на `/` і відкривають `index.html` у каталозі — переписування адрес не потрібне.
- Старі адреси чинного сайту (`/posts/…/`, `/personas/…/`, `/entrant/` тощо) збережено, тож перенаправлення не потрібні.
